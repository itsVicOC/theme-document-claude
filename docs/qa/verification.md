# Document Claude 1.1.0 验证记录

日期：2026-10-28。修改基线：`6db6600`。本次修改与验证均在本地完成。

## 环境

- WordPress 7.1.3，PHP 8.3.33，WordPress Playground 3.1.61。
- Node.js 24.18.0、npm 11.16.0、Dart Sass 1.106.1。
- 浏览器：Codex 内置浏览器，使用 CUA 真实页面交互、视口覆盖与只读 DOM 测量。
- 预览：`http://127.0.0.1:9400/`。测试数据为隔离环境生成的中文长文、英文、图片、宽表格、代码、两级菜单、小部件和评论；没有修改线上数据。

## 布局与交互结果

55 个布局场景通过：以下 11 个宽度分别验证首页、文章、聚合、留言与搜索空结果页面：

`320 / 390 / 480 / 481 / 768 / 1023 / 1024 / 1025 / 1279 / 1280 / 1440px`

所有场景页面宽度均未超过视口；导航、左右栏和移动目录符合断点；表单字号至少 16px。检查包含连续调整视口与重新加载。

12 项交互检查通过：

1. 折叠目录点击后关闭，章节停在顶栏下方（390px 下实测约 80px，顶栏 56px）。
2. 菜单高度与视口一致，背景锁定，焦点进入关闭按钮。
3. Tab/Shift+Tab 焦点留在抽屉内。
4. 两级子菜单能够独立展开，父链接保留。
5. Escape 关闭菜单，恢复焦点、背景可操作状态与原滚动位置。
6. 菜单展开时切换桌面宽度，抽屉状态与滚动锁正确清理。
7. 关闭目录配置时，不输出移动或桌面目录。
8. 左侧缩略图配置正常；无图文章没有空缩略图占位。
9. AJAX 分页将文章由 5 篇增加到 10 篇。
10. 原生搜索提交正确，空结果页面无溢出。
11. 未启用侧栏时不预留空间，主内容居中。
12. 评论回复链接、回复目标和表单滚动保持有效。

额外验证了 1280px 与 1440px 的桌面两级下拉菜单：展开后两个菜单均位于视口内。

宽表格实测为约 1025px，手机滚动区域约 316px，页面本身不横向滚动。代码块也在自身容器内滚动。

## 复现与截图

运行 `npm ci && npm run build && npm run dev` 后，可通过 Codex CUA 运行：

```js
const checks = await import('file:///你的项目绝对路径/tests/browser-checks.mjs');
await checks.runWidths(tab, viewport, '/');
await checks.runInteractions(tab, viewport);
```

`tab` 与 `viewport` 为 CUA 提供的浏览器页签及视口能力。对比截图使用相同本地内容和原始提交导出的主题；通过仅存在于临时预览的 MU 插件选择修改前版本，插件不会进入安装包。

[打开可视化对比](../visual-review.html)。截图在 [screenshots/](screenshots/)。

## 安装包与兼容

1.1.1 安装包为 `dist/theme-document.zip`，`style.css` 位于 ZIP 根目录；保持文件名不变时安装目录为 `theme-document/`，与当前线上目录一致。后台上传并替换现有主题文件，可沿用目录相关的菜单绑定；其他安装目录需保持原目录名。

主题配置键、菜单位置、短代码、文章 URL 和分页接口保持兼容，没有数据库迁移。SCSS 与生成 CSS 均包含在主题包中；开发依赖、脚本、测试、报告和截图均不进入安装包。网站运行不依赖 Node.js。

更新前保留当前主题文件副本，便于回退。安装后如使用整页缓存插件，请刷新页面缓存。

## 验证边界

当前只有内置浏览器可用于自动化，没有独立连接的 Safari/Chrome，也未进行 iOS/Android 真机测试。移动 Safari 的软键盘、安全区和双指缩放仍需在真实设备上复核；本次已经移除 viewport 缩放限制，并加入动态视口高度与安全区回退。
